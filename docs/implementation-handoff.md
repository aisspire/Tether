# 实现交接

## 1. 当前事实

2026-10-21 实现更新：已建立后台、页面、版本化配置、OpenSSH 运行和 Oriel 接入。准确运行入口见 [README](../README.md)，接口见[实现契约](implementation.md)，实际结果及剩余工作见[验证记录](../verification.md)。下文初始事实和建议顺序保留为交接背景；验收矩阵并不代表全部场景已通过。

工具名称为 Tether。本目录是独立 Git 仓库，位于 Oriel 工作区的 `plugins/external/tether/`，父仓库忽略该目录。仓库可单独移动或克隆，不依赖该嵌套位置运行。

初始交接时只有设计、开发约定与忽略规则：没有 Cargo／前端项目、锁文件、可执行入口、`oriel.ps1`、真实插件声明或业务测试。Git 初始化、文档检查和父仓库设计同步都不代表功能实现。

实现时先读[开发约定](../AGENTS.md)、[当前设计基线](design/current-design.md)，再读相应专题。核心行为已经确定，不需要重新询问是否 Windows 优先、是否保护已有连接、是否逐端口关闭或退出时如何处理外部 SSH。

## 3. 建议实施顺序

### 阶段 A：独立运行基础与转发闭环

- 核对 Windows Node、Rust、OpenSSH 和项目依赖状态，声明所需版本与包管理器，不自行全局安装。
- 建立 Vue／TypeScript 前端、Rust 本地后台及必要打包入口。产品可独立启动，后台与界面分层。
- 建立本地版本化配置、主机、规则、稳定 ID 和运行连接登记。
- 完成本地 SSH 转发、临时转发、增量启动、并发去重、同批分组、状态、日志和按组停止。
- 处理首次认证、隐藏窗口、实际就绪、保活、断线重连和取消。
- 为普通远程／动态转发沿用同一模型，准确记录未完成范围。

### 阶段 B：计划、观测、参数与 SSH 管理

- 批量计划、一键启动、复用摘要、冲突和部分失败。
- 只读明确外部观测、备注、分组和单一响应时间。
- 常用 SSH 表单、高级有序 `-o`、临时覆盖、生效参数预览。
- 原始 SSH 配置访问与编辑、Include／Match／跳板兼容和运行快照。
- 密钥／Agent／known_hosts 视图与工具操作，保留正确的文件、认证和退出边界。

阶段 A 需要的配置解析与认证不能推迟到阶段 B 后才补正确性；这里按交付重心排序，不允许先用错误配置临时凑功能。

### 阶段 C：公共动作与 Oriel 集成

- Tether 提供后台控制、生命周期入口和按规则 ID 的确保可用动作。
- 先验证后台无页面也能处理请求，独立 UI 和 CLI 使用同一业务路径。
- Oriel 增加声明、托管进程、真实就绪、前置动作等待和退出清理。
- 联调浏览器页面的前置转发、复用、失败重试、多个使用方和退出策略。
- 宿主修改属于另一个 Git 仓库，核对工作目录，分别记录变更与验证。

阶段划分是实现建议，不是已经批准遗漏其他已确认需求的理由。未完成项需要在实现状态和最终交付中清楚列明。

## 4. 重点技术问题

| 问题 | 必须保持的行为 |
| --- | --- |
| SSH config 自带转发 | 新批次不会重复绑定旧端口，原文件不被自动改写 |
| Include、Match、token 与跳板 | 保留原生语义；无法支持时明确失败，不静默改目标或认证 |
| `ssh -G` | 不作为无副作用高频扫描；输出需解析，不能直接回写原文件 |
| Quiet、隐藏窗口和认证 | 不混为一项，不隐藏需要输入的状态，也不伪造就绪 |
| Windows 进程和子进程 | 只清理有明确归属的组，不结束外部 Agent 或所有 ssh.exe |
| 重连与停止竞争 | 明确停止先取消重连，旧回调不能再次启动或覆盖新代次 |
| 并发前置请求 | 相同规则共享启动结果，不重复绑定，不重启旧连接 |
| 本地服务接口 | 独立与嵌入均可用，任意网页不能直接控制 SSH 或密钥 |
| 密钥和 Agent | 文件、只含公钥、Agent-only 与硬件身份区分，不复制未知私钥 |
| 单一响应时间 | 方法和目标准确，不能显示本机监听耗时为远端延迟 |

字段、控制通道、依赖版本和内部目录可由实现收敛；影响核心行为的取舍才需要单独讨论。

## 5. 行为验收矩阵

以下为完整验收目标；已覆盖项以[实际记录](../verification.md)为准，不代表整张矩阵均已通过。测试应使用隔离目录、受控 SSH 服务和临时身份，不修改真实用户 SSH 配置，不连接未经授权的远端。

| 编号 | 场景 | 期望 |
| --- | --- | --- |
| V01 | A、B 已运行，启动包含 A～D 的计划 | A、B 的进程与现有通道保持；仅 C、D 新建 |
| V02 | 同一批同主机兼容参数的多个转发 | 尽量由同一个新 SSH 承载，组内规则可追溯 |
| V03 | 同 IP 不同用户、密钥或跳板 | 不错误合并上下文 |
| V04 | 双击启动或两个计划并发请求相同规则 | 共用一份启动结果，不出现重复监听 |
| V05 | 重复执行已成功计划 | 复用已有结果，不创建新进程 |
| V06 | 一个新组失败，其他组或旧组正常 | 故障范围限定，不回滚其他连接 |
| V07 | 外部进程占用相同端口 | 显示冲突或明确外部来源，不视为已托管 |
| V08 | 停止连接组 | 组内监听和已有通道按范围结束，不影响其他组 |
| V09 | 停止主机或全部托管连接 | 仅清理对应拥有的进程及子进程，外部 SSH／Agent 保留 |
| V10 | 在重连退避或认证等待时停止 | 重试和交互取消，之后不被旧任务拉起 |
| V11 | 网络断线与恢复 | 组按策略重连，原有运行快照保留 |
| V12 | 密码错误、主机指纹变化、配置错误 | 明确错误并暂停，不持续快速重试 |
| V13 | 配置含已有 LocalForward，新计划只补一条 | 已运行转发不被继承重绑，仍保持原连接 |
| V14 | Include、Match、多跳与临时 `-o` | 生效目标、认证和转发清单与预期一致 |
| V15 | 规则名称、备注或排序修改 | 稳定 ID、引用和运行连接不变 |
| V16 | 修改运行规则的实际参数 | 显示待应用，不自动替换；显式重启才更新 |
| V17 | 删除计划或正在运行规则的登记 | 不隐式停止，运行项仍可见并可管理 |
| V18 | 外部编辑同时修改 SSH 文件 | 检测冲突，不覆盖未知新内容 |
| V19 | 配置损坏、版本不支持、保存失败 | 保留原文件并准确反馈，不能显示已保存 |
| V20 | 临时托管项保存成规则 | 登记成功并关联现有组，不重启 |
| V21 | Agent-only 身份、只有公钥或加密私钥 | 正确显示来源，不要求解锁所有身份或伪造文件 |
| V22 | 生成密钥、加载／移出 Agent、复制公钥 | 作用准确，口令不进入日志或命令预览 |
| V23 | 首次主机确认、口令和多因素认证 | 交互可见且可取消，后台不永久无响应 |
| V24 | 首次与主动响应测试 | 只更新一个值，目标与方法准确，无数据可表达 |
| V25 | SSH 进程存在但转发未就绪 | 前置动作不错误返回 ready |
| V26 | 页面按规则 ID 请求已运行或正在启动的转发 | 复用并等待，不重启 |
| V27 | 多个页面共享前置转发，其中一个关闭或加载失败 | 连接继续，其他页面不受影响 |
| V28 | 用户停止后页面状态轮询或切换 | 不自动强制重开；明确重试才发新请求 |
| V29 | 完全退出 Oriel | 托管转发中断、重连取消，外部进程保持 |
| V30 | 端口匹配外部 SSH 或旧 PID 被重用 | 不因匹配或历史记录获得管理权 |
| V31 | 生命周期入口缺失、后台未就绪或动作超时 | 宿主诊断准确，不把脚本退出当业务就绪 |
| V32 | 任意外部网页请求本地控制接口 | 不能越过调用身份与来源边界控制资源 |
| V33 | 浅深主题、窄窗口、长列表与键盘操作 | 核心任务可到达，停止范围与状态清楚 |

## 6. 验证与交付纪律

独立单元与集成验证优先覆盖运行规划、归属、并发、取消、配置写入和动作结果。Windows 原生验证覆盖进程、认证、监听、Agent 和打包；网页预览不代替这些结果。

按实际改动选择必要检查，不编写只复述实现的测试。记录本轮实际命令、结果和缺口；过去文档或其他项目的构建结果不能沿用。

依赖声明出现后保留包管理器与锁文件。不得为完成验证自行安装系统或全局工具。不要自动创建 commit、远程仓库、推送或发布。
