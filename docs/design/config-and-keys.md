# 本地配置、SSH 参数与密钥

状态：本文保留已确认的产品要求；已实现部分、准确字段和当前限制见[实现契约](../implementation.md)及[实际验证](../../verification.md)，下文候选方案不等于全部已交付。此处细化[当前基线](current-design.md)，不冻结最终字段、库或配置格式。

## 1. 唯一编辑来源

| 内容 | 权威来源 |
| --- | --- |
| SSH 主机、认证、转发与协议原始配置 | 用户选择的 SSH config 及其包含文件 |
| 密钥、公钥、主机指纹与证书 | 原有身份文件、known_hosts 和对应本地工具 |
| Agent 中已加载的身份 | 实际 Agent 状态，不假设每个身份都有本地私钥文件 |
| Tether 规则、计划、备注、覆盖和界面偏好 | Tether 自己的本地配置 |
| SSH 程序路径、配置路径、外部编辑器 | 当前设备的本地绑定 |
| 连接组、启动结果、观测和日志 | 运行记录，不能作为用户可编辑配置的第二个来源 |
| Oriel 的插件位置、启动策略和前置依赖 | Oriel 本地配置，只引用 Tether 的规则或计划 |

不把用户整份 SSH 配置导入应用数据库后独立维护。来自 SSH config 的转发应保留文件和条目来源；若用户显式另存为 Tether 规则，需清楚区分来源和未来编辑归属，防止重复绑定。

规则稳定 ID 不依赖主机名、端口、备注或排序。具体配置需要版本、默认值、校验、原子保存和迁移；损坏文件不静默重置或覆盖。

## 2. 主机与转发登记

主机可以引用已有 SSH 别名，也可以填写 user@server 并设置覆盖项。主机内统一管理连接与批量端口映射，不再设置主机分类。相同 IP 的不同用户、身份或跳板上下文不自动折叠为同一个连接配置。

转发规则至少要能表达：

- 稳定 ID、名称、备注和可选标签。
- 主机配置引用和原始配置来源。
- 本地、远程或动态方向。
- 监听地址、端口与地址族。
- 固定目标地址、目标端口；动态转发使用自身语义。
- 必要的连接覆盖及保活／重连策略引用。

目标地址从 SSH 哪一侧解析与连接，需要在编辑界面清楚表达。端口范围、IPv6、空地址和通配监听要校验。默认监听本机回环是建议默认值，用户显式修改后按其选择处理，不擅自改变已有规则。

临时启动使用同一套运行规划，只是不写入规则登记。点击保存时获得稳定登记，仍关联原运行连接，不重启当前 SSH。

## 3. SSH 参数入口

### 常用表单

常规入口保留 SSH 目标／别名，不重复提供用户字段。常用表单提供端口、身份文件、跳板链、保活间隔和地址族；其他参数从可搜索目录添加覆盖项。User 高级覆盖与目标内用户冲突时校验失败；表单、高级覆盖行和原文共用同一份有序 options，恢复继承只移除对应覆盖。

多跳主机应允许使用各自的配置身份，不把目标主机的全部 `-o` 或密钥参数误套到每一跳。优先沿用原有配置表示跳板差异。

### 高级入口

参数目录列出 OpenSSH portable 10.0 文档的全部 102 项配置指令，含仅能在原始配置、专用映射或 Tether 托管设置中处理的项；这些项说明原因且不能作为覆盖添加。本机 Windows OpenSSH 的版本与编译能力可能不同，目录不冒充本机支持清单，以用户显式检查生效参数和实际启动的原生反馈为准。目录维护来源见[参考资料](../references.md)。

- 支持有序的 `-o 名称=值` 项，允许 OpenSSH 本来支持的重复或累积设置。
- 临时覆盖只影响本次请求；显式保存后才成为规则或主机配置的一部分。
- 其他参数可使用结构化参数列表，不用未经解析的 shell 字符串拼接。
- 提供最终程序、参数和实际生效设置预览，隐去敏感内容。
- 客户端不支持或与托管模式冲突的选项要报告原因，不默默忽略。

不能假设所有选项都是普通的“最后一个覆盖前一个”。配置解析应尽量依赖本机 OpenSSH 的实际行为，使用单值、多值和选项顺序的必要验证。

### 静默与托管

以下分别设置，不共用一个含混的“静默模式”：

| 设置 | 含义 |
| --- | --- |
| 隐藏本地控制台 | Windows 不额外弹出命令窗口 |
| 仅转发 | 不执行远端交互 Shell 或业务命令 |
| 日志级别 | SSH 输出的详细程度，包括 quiet 与调试 |

`-f`、ForkAfterAuthentication、控制 socket、远端命令和会改变进程生存关系的选项，需要与运行模式协调。首版保留 Tether 对进程与就绪状态的控制，不通过任意后台化参数丢失归属。

## 4. SSH config 访问与编辑

提供打开配置文件、在系统或用户选择的编辑器中打开，以及内置文本编辑入口。内置编辑也以原始文件为对象，不把它重写成工具专属 schema。

需保留注释、空行、顺序、Host 通配符、Include、Match 和未知但有效的设置。不能把 `Host *` 等模式当成一个实际可直接启动的主机。可视化编辑只处理能明确定位并可靠保存的条目；复杂结构可转原文编辑。

建议的编辑流程：读取文件与修改标识，编辑，比较外部变化，必要时提示冲突或重新加载，保存前校验，备份并安全写入，反馈实际结果。Windows 权限或文件锁定失败不能显示保存成功。

保存文件不重启现有连接；受影响连接显示配置待应用。外部编辑后的重新加载更新登记视图，但不把当前配置假称为旧进程的历史参数。

## 5. 生效配置与运行快照

`ssh -G` 可以帮助获得指定主机在本机客户端下的生效结果，但不能把其输出未经处理当成可无损回写的配置文件。复杂 token、路径、列表、来源信息和跳板身份需要保留正确语义。

解析 Host／Match 时可能执行配置中的 `Match exec`。读取原始文件与请求实际解析是不同动作，不在后台端口轮询中高频自动运行这类解析。

增量启动尤其要处理原文件中的 LocalForward、RemoteForward 和 DynamicForward。新进程若直接再次引用原主机，可能重绑旧端口。`ClearAllForwardings` 会同时影响命令行转发，不能把它当成只清除文件转发的通用解决办法。

建议形成独立的启动规划与运行配置编译层：

1. 解析目标主机、跳板及必要连接上下文。
2. 合并本次覆盖，并显示实际生效意图。
3. 将所有来源的转发纳入规则清单，识别已有项与冲突。
4. 为本批生成只包含待启动转发的运行配置或等效执行描述。
5. 启动后保留该次参数快照和来源记录。

这是需要重点验证的实现方案，不代表已经解决全部 OpenSSH 配置语义。若无法可靠保持某种复杂配置，明确报告受限范围；不能用关闭旧连接来规避它，也不能静默更改认证或目标主机。

## 6. 密钥和 Agent 列表

发现来源包括默认 SSH 目录、配置引用、用户登记路径和实际 Agent 身份。只在这些明确范围内查找，不全盘扫描用户文件。

条目可展示名称、算法、长度或类型、SHA256 指纹、公钥备注、文件位置、是否存在本地私钥、是否已加载 Agent、已知主机引用和可辨识的加密状态。

当前 UI 以公钥算法与密钥数据关联文件和 Agent 身份，显示 `ssh-keygen` 提供的 SHA256 指纹并保留来源；完整指纹合并仍是后续完善方向。Agent-only 身份、硬件身份和仅有公钥的项都是合法情况，不伪造私钥路径，也不因列出密钥而要求解锁全部身份。

## 7. 密钥可视化操作

- 生成客户端支持的密钥，选择位置和密码短语。
- 登记或导入已有文件；优先保留原路径，复制行为需明确。
- 查看指纹、复制或导出公钥、打开文件位置。
- 修改密码短语或公钥备注，按工具实际能力反馈结果。
- 加载与移出 Agent，显示执行结果和支持的约束。
- 检查文件引用后删除本地文件，准确说明影响范围。

优先使用 `ssh-keygen`、`ssh-add` 等现有工具。客户端算法、硬件密钥和 Agent 能力不同，按实际检测展示，不承诺未验证功能。

从 Tether 列表移除、删除私钥文件、Agent 卸载和服务器撤销授权分别表达。删除本地文件或 Agent 身份不会自动撤销远端公钥。远端密钥分发与 authorized_keys 管理不是已要求的首版能力。

## 8. 认证与主机指纹

首次主机确认、已变化的主机指纹、用户密码、加密私钥和多因素输入必须有可用交互。后台模式也需要能通知界面或调用者，不允许隐藏窗口后一直等待不可见输入。

known_hosts 与客户端身份密钥分开管理。不要为省去交互自动关闭主机验证；主机指纹变化属于需处理的错误，不按普通网络问题持续重试。

私钥和密码短语不写入规则、命令预览、日志或错误详情；必要的口令输入不以可见进程参数传递。持续保存凭据的机制未冻结，不能直接把明文放入本地 JSON。

Agent 不可用时报告当前状态，不擅自安装、启用系统服务、修改全局配置或提高权限。

## 9. 文件与运行数据建议

本机用户配置目录保存版本化规则、计划与偏好；临时运行目录保存生成配置、实例发现与必要状态；日志和缓存单独管理。准确路径、保留周期、敏感字段和清理方式在实现中确定。

生成配置不是新的用户编辑权威。后台重启后，旧 PID 文件不能作为接管依据；需重新验证实例、进程归属和实际状态。自动启动计划也不能冒充已经恢复的运行连接。

文档示例使用占位主机、隔离目录和临时身份。真实 SSH 文件、私钥、凭据与运行快照不得进入源码仓库。
