# 设计决策记录

日期：2026-10-24。本文记录已确认选择、必要理由与待定建议，当前完整要求以[设计基线](current-design.md)为准；设计记录不表示功能已经实现。

## 2026-10-24：单条映射复制完整链接命令

用户要求在映射“更多”菜单的“复制规则 ID”下方增加“复制完整链接命令”，明确只针对一条映射。先完成需求分析，用户随后授权开发，现已实现。

代码核对发现，当前运行参数属于连接组，可能含多条转发，并以 `-F` 引用 Tether 生成的运行快照；直接复制无法满足单条范围与可独立粘贴执行的目标。新增 `connectionCommand` 业务动作，按当前登记或临时运行快照生成单条 OpenSSH 命令；通过 `-F none` 与必要的生效参数隔离其他转发，跳板逐跳生成无配置文件依赖的代理命令，并由同一客户端回读校验。Windows 输出 PowerShell 命令，已有 WSL 输出其 shell 命令；复制保留异步生成前的用户手势并提供成功／失败反馈。特殊跳板 token 和不能可靠复现的配置明确拒绝，详见[界面设计](ui.md)及[实现契约](../implementation.md)。该需求属于 Tether 业务能力，不修改 Oriel 插件接入或生命周期契约，实际检查见[验证记录](../../verification.md)。

## 2026-10-23：长列表排序与弹窗误触保护

用户要求拖拽排序支持屏幕外项目的可达性、关闭键固定右上角，并明确窗内按下、窗外松开不能退出或弹出保存确认。主机、映射和计划复用稳定 ID 的数组顺序，主列表直接保存，编辑列表随草稿保存；以边缘持续滚动支持长列表。弹窗统一固定顶部栏，并结合按下与松开的坐标判断窗外完整点击，避免拖选文字或跨边界手势误触关闭。实际验证边界见[验证记录](../../verification.md)。

## 2026-10-22：检测收窄到已有映射，调整密钥与延迟展示

用户取消网页快捷入口和外部 SSH 总览，仅关心已登记／临时映射。终端建立的 SSH 匹配完整映射及可确认上下文时，更新原映射的运行状态；关联不授予停止、重连和退出清理权限。检测轮询不调用可能触发 Match exec 的原生解析，未知上下文保持未确认，远程监听不冒充已就绪。

密钥中部改为文件列表及独立 Agent 区，分层显示路径、指纹和类型，按文件提供主要操作和展开详情。响应时间沿用原位置，按用户补充主要调整颜色，保留测试中和无法测量文字状态。旧网页字段兼容读取后丢弃，保留其他配置及稳定引用。

## 2026-10-22：以主机为中心的使用体验

用户授权一次完成此前讨论的调整：合并主机与转发入口，主机内批量编辑映射，计划按主机选择固定映射集合；新增映射不自动加入已有计划。常规 SSH 入口只保留目标／别名，不重复设置用户；参数提供版本化完整目录、结构化控件与统一有序覆盖。移除主机分类入口，内部稳定 ID 在详情复制。

同一映射只展示一行，运行连接和日志按需展开。成功停止后移除记录，不保留连接历史；失败信息可关闭且不授予活动连接管理捷径。加入保存与启动分离、引用影响提示、整台主机级删除、未保存保护、批量导入预览、局部操作反馈、仅重试未就绪项、搜索筛选、地址复制；其中可选网页入口已由同日后续决定移除。具体交互见[界面设计](ui.md)，实际验证另行记录。

## 2026-10-22：说明入口与独立应用核对

用户认可既有三层职责、独立仓库、配置与运行分离、增量连接管理及退出边界。新增确认要求：Tether 提供说明文档，能在应用内部点击打开。设计核对时只有仓库文档；随后用户授权实现，已加入随包 USER_GUIDE.md 和独立页面阅读弹窗，宿主也能读取同一文件，内容要求见[界面设计](ui.md)。

当前本地 HTTP 页面使独立浏览器和 Oriel 共用 UI。用户进一步明确独立桌面应用并非必要，同类插件应按工具应用布局展示，并考虑后续很多工具接入。采用通用展示模式的方向：浏览器保留地址栏与导航，Tether 等工具应用不显示浏览器地址栏和通用浏览导航，保留必要宿主窗口与管理能力、插件内说明入口，业务导航由工具负责。

展示模式与页面技术和后台生命周期分开，通过通用声明选择，不按 Tether ID 或 URL 特判，后续兼容工具复用同一宿主能力。实现已采用版本 2 的 `presentation: "application"` 和 `documentation: "USER_GUIDE.md"`；不为移除地址栏引入独立桌面外壳，Tether 继续保留现有独立运行方式。

用户授权后，Oriel 已实现默认及额外读取目录自动发现，并兼容显式路径；不增加 Tether 自注册或扫描宿主目录的职责。独立说明编入 UI，原文件随包提供；调试交付包、独立 UI 与宿主隔离联调已验证，准确结果见[验证记录](../../verification.md)。

## D01：独立的本地 SSH 工具

先完成普通 SSH 转发，再完善 SSH 管理。采用独立仓库和独立运行方式，Oriel 通过能力接入，不要求工具业务迁入宿主。

脚本面板和服务器监控不作为当前产品范围。SSH 转发具有明确的登记、启动、状态、重连和停止闭环，适合先完成可独立使用的工具。

名称为 Tether。本机开发目录采用 Oriel 工作区内的 `plugins/external/tether/`，目录拥有自己的 Git 仓库，父仓库忽略该目录，不注册子模块。开发位置不成为运行时或分发依赖。

## D02：Windows 原生 OpenSSH

首版只考虑 Windows，优先使用本机 OpenSSH 和原有配置、密钥工具。Vue 3／TypeScript 界面、Rust 本地后台与系统 SSH 分层，独立与嵌入复用同一页面。

不先自行实现 SSH 协议或增加 WSL 环境，也不把 Windows Service 作为先决条件。精确版本和依赖在实现时声明。

## D03：启动保护优先

最核心的要求是新增转发不打断既有连接。已有转发复用，缺失项另起新批次，同批参数兼容时尽量使用一个 SSH。

不为减少进程数而重建旧连接，不因为配置保存或页面变化自动重启。逐端口独立关闭不作为首版优先条件；停止按实际连接组、主机或全部处理。

因此首版不依赖 ControlMaster，不为逐端口取消增加内部 SOCKS 中继。未来如需更细控制，再依据实际客户端能力设计。

## D04：登记、关联与管理权分离

已登记规则、临时转发、实际进程、启动计划和外部观测分别建模。临时转发只要由 Tether 创建，仍可停止并保存为规则。

匹配到相同规则、端口或命令不意味着可以接管外部进程。只展示明确外部信息，其他工具和终端建立的连接保持只读。

## D05：计划是启动清单

计划引用已登记规则，支持跨主机一键启动。重复执行复用已有项；计划修改或删除不改变正在运行的连接。

2026-10-22 用户明确确认：主机后续新增端口映射不自动纳入已有计划。即使以主机为单位全选，也只保存当时选中的规则 ID，避免原有计划在未编辑时扩大启动范围；执行仍读取这些规则的当前参数。

自动执行计划与启动 Tether 本身分开配置。计划不持续强制调和全部规则，用户停止后不能马上又自动拉起。定时与复杂工作流另行设计。

## D06：保持本地配置权威

原有 SSH config、身份文件、Agent 和 known_hosts 各自保留原来源。Tether 保存业务规则、备注、计划、覆盖和引用；Oriel 只保存接入与依赖。

支持原文编辑和外部编辑器，保留 Include、Match、注释与顺序。运行快照属于生成结果，不另建可竞争编辑的主配置。

## D07：单一响应时间

界面只保留一个响应值，首次测试和主动测试更新同一位置，不并列展示连接建立耗时等多项指标。

默认以 SSH 地址 TCP 响应作为起步方案，无法可靠测量时显示无数据；本机监听响应不能冒充远端响应。方法和更新时间放在详情中。

## D08：由 Tether 执行，Oriel 调度

Oriel 负责生命周期和前置动作通用流程，Tether 负责 SSH 创建、状态、保活、重连与停止。保留一个真实连接管理来源，避免两边分别监督同一个 SSH。

Windows 入口采用 `oriel.ps1` 方案。需要托管的声明缺少有效动作入口时报告诊断；不将同名脚本强制推广到纯网页和仅连接既有服务的插件。

## D09：前置资源按规则 ID 请求

例如浏览器打开页面前，按稳定规则 ID 请求转发；已运行或正在启动时复用，缺失时增量创建，转发就绪后再打开依赖页面。

相比推断原始 SSH 命令，明确规则引用能够稳定对应登记，保持配置只有一个来源，并确定运行归属。原生命令的匹配只提供关联；Oriel 若直接创建并跟踪进程，由 Oriel 自己管理。

## D10：会话结束统一清理

前置转发默认保持至本次 Oriel 会话结束。多个页面可以使用同一个连接；切换、隐藏、关闭页面或页面加载失败不自动回收。

完全退出 Oriel 时，停止接入实例的 Tether 托管转发并取消重连，外部 SSH 保持不动。规则和计划保留，不等于运行连接持续存在。

不为首版增加按每个页面关闭而回收的引用计数机制。使用方关联仍需记录，供展示影响范围和排查。

## D11：当前宿主能力与设计分开

Oriel 当前网页声明能力不等于已经支持生命周期和前置资源。Tether 可以先独立实现，接入需要扩展宿主；字段、公共动作和控制通道在真实联调中收敛。

新增宿主能力可以要求升级 Oriel；形成兼容能力后，新增兼容插件无需为其重编译。当前不提前发布通用 SDK 或完整工作流协议。

## 2026-10-21 实现收敛

采用受身份与来源校验的随机回环 HTTP 提供独立页面，stdio-v1 供宿主管理；SSH 闭环与 UI/CLI/Oriel 使用同一运行规划。Windows 先暂停创建进程、加入 Job Object 后再恢复，避免跳板子进程逃逸。原生配置经显式解析和回读核对后形成快照，不能可靠保留的语义明确拒绝。核心启动保护、外部只读与完整退出边界保持不变。准确接口与未完成项见[实现契约](../implementation.md)。
